# C5G7 2×2 assembly-placement smoke-run results

## Status

**Six of six low-budget OpenMC transport runs completed** in the GitHub Actions smoke workflow using OpenMC 0.16.0 and upstream source commit `ba41bee54320ada0b4ac39a0dd2ca3c1d090a450`. These results are exploratory software/model-execution evidence, **not benchmark-grade results and not a reactor design recommendation**.

## Common run settings

- 100 total batches, 10 inactive, 1,000 particles per batch, 1 thread (90 active realizations).
- Explicit per-candidate seeds: 620000–620005.
- All six candidates used the same MGXS SHA-256: `170cc799f496e952465583bb078b2a88eae0f09886a821fd7ee8999d1eb93216`; before/after hashes match and no pre-existing files were mutated.
- Each run has a candidate ID, layout, settings hash, statepoint hash, and recorded input/output hashes in the compact run manifest.
- Full statepoints, logs, generated inputs, and detailed tally arrays remain in the [workflow artifact](https://github.com/thenextw4ng/cb-pfr/actions/runs/38085586809). A later raw-HDF5 audit of the six statepoints passed 112/112 checks; the compact result is committed in [raw_hdf5_audit_summary.json](../results/c5g7_layout_smoke_2026-10-10/raw_hdf5_audit_summary.json), and the [audit run](https://github.com/thenextw4ng/cb-pfr/actions/runs/38097364817) preserves the full JSON.

## Canonical layout cross-check against production baseline

The canonical layout (`c5g7-2x2-UMMU`) produced k_eff = 1.18817927 ± 0.00304792; the production statepoint reported 1.18639414 ± 0.00005611. The absolute difference is 0.00178513, or 0.59 combined reported standard deviations. Both runs use the same MGXS hash and the generated canonical geometry XML hash matches the production geometry hash, but the materials XML and settings differ. Treat this as a useful consistency signal, not formal benchmark verification.

## Interpretation and limitations

1. The six layouts are an explicitly reformulated 2×2 UO2/MOX assembly-placement study. This is separate from the legacy abstract `fresh / once_burned / twice_burned` QUBO; no mapping between them is implied.
2. The canonical arrangement is a baseline identity check. The other five layouts are design variants, not official C5G7 benchmark reference cases.
3. Each layout has only one low-budget run. Different layouts have different seeds, but this does not estimate same-layout repeatability. Run several independent seeds per layout before making reliability or ranking-stability claims.
4. The reported tally scores are flux, fission, and nu-fission. They are not automatically absolute power in watts. Any power-related analysis needs a documented normalization and benchmark-compatible comparison protocol.
5. The k_eff order is not itself an objective. Do not select a layout merely because its k_eff is lowest or highest. Predeclare the physical objective, constraints, and acceptance criteria before a benchmark-grade run.
6. The smoke settings (100/10/1000) are for pipeline verification and have relative uncertainty of about 0.22–0.26%. They are not sufficient to claim convergence or benchmark acceptance.
